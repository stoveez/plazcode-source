User-selected username/password accounts, revocable 90-day remembered sessions, private settings/skills documents with revision conflict protection. Passwords use salted scrypt (N=32768,r=8,p=3,32-byte output); session tokens are random and only their hashes are stored server-side. One-use proof challenges, bounded request/data sizes and quotas limit abuse. No shared app secret is shipped. Portable preferences exclude local paths and access permissions. Memory stays isolated locally per profile. The service does not expose an account list.

Recovery email/reset remain separate work; this service implements profile sign-in, settings/skills sync, presence heartbeats (`POST /v1/heartbeat`), ban/unban/removal enforcement, and the owner moderation directory (`GET /v1/owner/users`, `POST /v1/owner/users/:id/{ban,unban,remove}`, `DELETE /v1/owner/users/:id`) gated behind `OWNER_USERNAMES` or `OWNER_ADMIN_TOKEN`. Password salts/verifiers and private synced settings/skills are never exposed in owner responses; only bounded profile pictures (`rsProfilePicture`), join timestamps, presence, and ban metadata are returned.

Profile pictures sync privately through rsProfilePicture: only bounded JPEG/PNG/GIF data (1 MB decoded limit), no external URLs/SVG. Omitted fields from older clients retain the existing picture; explicit null removes it.

# gui-references

Use this user-provided reference only when it helps the current project request. Adapt paths, assets, style and APIs to the actual project and available PlazCode tools. The current user scope takes priority. Keep working features. Do not impose extra search loops or ask the user to continue after every component. Use actual tests when tools permit; report what remains untested.

When relevant: looking for examples, layouts, design ideas or how other games solve an interface problem.

Know which sources you can reach, and what each one is good for.
- Reference library (see reference-library): check it first.
- Roblox docs (fetch_roblox_doc): the authority for how an API works. Use it for any claim about
  properties, events, or what a UI object does.
- Studio Toolbox (search_creator_store): ready-made interface pieces. See gui-toolbox.
- YouTube, TikTok, Discord, GitHub and forums: the model cannot search or open these from here. Ask
  the user to paste the link, or the text or code they want to share. Say what you need from it,
  such as "the layout of the shop screen" or "how they handle the close button on phones".
- Treat any pasted example as a reference for layout and feel, not as code to copy. Check its
  license first if it is code. Do not copy a whole screen; take the idea and build it with the
  rules in gui-layout and check-ui-standard.
- Video and social posts are opinions. Use them to find ideas, then check the idea against the
  Roblox docs before you rely on it.
- In the report, list every reference you used, by the link or name the user gave you, and say
  what you took from it.

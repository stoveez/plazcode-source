# report-what-you-verified

Use this user-provided reference only when it helps the current project request. Adapt paths, assets, style and APIs to the actual project and available PlazCode tools. The current user scope takes priority. Keep working features. Do not impose extra search loops or ask the user to continue after every component. Use actual tests when tools permit; report what remains untested.

When relevant: the end of every UltraGUI task.

Finish with:
- Screens: each screen, marked done, stuck (with the reason), or not started.
- Style: the Check-UI archetype used, or "plain" if none.
- Pack: the approach chosen and why, with its version and license if it is a library.
- References: each link, file or name the user gave you, and what you took from it.
- Toolbox used: each asset's name, creator, asset ID and what changed, or "none".
- Docs read: each docs address you fetched, and what it confirmed. List any you could not fetch.
- Checked by the numbers: the sizes checked, the three screen sizes, and the results.
- Checked by reading: the check-cycle results, and the cycles each item took.
- Not checked: anything that needs a person to look at the screen in play, a link you could not
  open, an asset ID you could not confirm, or a licence you could not read. Name the play-test steps.
Do not say "tested" or "looks good". Say what was measured, what was read, and what was not run.
